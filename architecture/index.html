Smart Wishlist · architecture

How one card gets chosen

The prototype decides in the browser, on every screen she opens. It starts from her entire Wishlist and throws almost all of it away. Every number below is the literal value in the code — the floors in SURFACE, the weights in W, the signal ranks in signalOf().

Nothing is authored

Every feature is read off the product's own Myntra fields — category into a slot, colour hex into hue and chroma, usage into occasion, price into a tier. There is no pair table and no per-item rule to maintain.

A change beats a match

A price drop, a size back in stock, or only a few left is a fact about the product, not a guess about her. On the bag, listing and search it skips scoring entirely. Scores only rank within a priority.

Silence is an answer

If nothing clears the floor for the surface she is on, the card does not render. That path is drawn because it is the one that runs most of the time, and it is what keeps the strip worth looking at.
